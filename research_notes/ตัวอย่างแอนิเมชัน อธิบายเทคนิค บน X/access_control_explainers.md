# Animated / motion explainers on X for access control, permission-aware RAG and data governance (research notes, 2026-10-20)

Scope note: these notes are for a ~90 s, 16:9 explainer (Thai on-screen text, English technical terms) about permission-aware RAG over a government organisation's multimodal archives. The core message: real permissions come from identity plus the ACL in the document registry, and every document, chunk, tree node and agent tool must be scoped BEFORE the search runs (never search everything and filter afterwards).

Method (so the writer can judge coverage):
- x.com returns HTTP 402 to WebFetch, and X search is not reachable, either through fxtwitter (`/2/search` returns 404) or through web search (`site:x.com` queries returned almost nothing). So I scanned account timelines through `api.fxtwitter.com/2/profile/{handle}/statuses` and `/media`. That covered 37 accounts: ByteByteGo/Alex Xu/Sahn Lam, Akshay Pachaar, Avi Chawla, Nikki Siapno, Pinecone, Weaviate, Qdrant, Elastic, Glean, Cerbos, Oso, Permit.io, Auth0, Okta, OpenFGA, AuthZed, Microsoft Mechanics, Microsoft Security, Varonis, AWS, WorkOS, Descope, Pangea, LlamaIndex, LangChain, Cloudflare, Victoria Slocum, Leonie Monigatti, Brij Pandey, Rakesh Gohel, Milan Milanović and others. I ranked posts by keyword relevance and media type, then pulled each candidate through `api.fxtwitter.com/{user}/status/{id}`. That call returns the engagement counts quoted below, as of 2026-10-20.
- **Coverage limit:** the timeline endpoint stops at about 850 statuses per account. For prolific accounts (Akshay Pachaar, Avi Chawla, Alex Xu) the scan only reaches about Nov 2025 for Akshay and Avi, and Oct 2024 for Alex Xu. Older 2023–2025 posts from them could only be found by luck. The vendor accounts, Leonie Monigatti, Victoria Slocum, OpenFGA, AuthZed and Cerbos were covered back to 2023.
- I downloaded 25 videos, GIFs and images into `media/ac-*/` (each folder has `video.mp4` or `image.jpg`, `sheet_NN.png` contact sheets with timestamps, and `meta.txt` with the media and post URLs). I looked at every contact sheet. All visual descriptions below come from those sheets.
- Engagement is low for almost all vendor posts that are actually on topic (often under 2,000 views). High-engagement creators (100k+ views) made no animated post about permission-aware RAG that I could find. Their highest-reach posts on access control are static diagrams.

## Which X posts/accounts explain permission-aware RAG or "RAG access control" visually (verified, with engagement)?

### Takeaway
Only a handful of X posts animate permission-aware RAG itself, and they are all vendor posts with small reach: AuthZed's "RAG without authorization" demo GIF, Auth0's "FGA for RAG" motion graphic, and Microsoft Mechanics' Purview/Copilot shorts. The most legible pre-filter vs post-filter visuals on X are static (Leonie Monigatti, Nikki Siapno) and would be easy to animate. High-reach creators (Avi Chawla, Akshay Pachaar, Level Up Coding, ByteByteGo) are worth copying for technique (flowing-dot connectors, single travelling token, step highlighting), not for subject matter.

#### 1. AuthZed — "Most RAG pipelines have a security problem nobody talks about" (GIF of an interactive demo)
- Link and author: [x.com/authzed/status/2072679204831768894](https://x.com/authzed/status/2072679204831768894), @authzed (SpiceDB), posted 2026-07-02. Engagement: 1 like, 0 reposts, 131 views (account has 1,544 followers). The format is a looping GIF, 6.0 s, 1000×1196 (near-portrait). It links to an interactive 5-step demo, [authzed.com/ai-authorization/rag-demo](https://authzed.com/ai-authorization/rag-demo). Source for all of this: [post via fxtwitter](https://x.com/authzed/status/2072679204831768894).
- Post copy: "Vector DBs retrieve documents based on semantic similarity, not on who's allowed to see them… it can come back with salary data, HR records, or confidential specs… The LLM doesn't know the difference." — [AuthZed post](https://x.com/authzed/status/2072679204831768894)
- What I saw (contact sheet `media/ac-authzed-rag-demo-gif/sheet_01.png`): a dark maroon UI headed "STEP 1 OF 5 · RAG Without Authorization" with a red "ACME CORP AI · AUTHORIZATION OFF" label. The user picker is set to "Bob (Eng)" and the question to "Q4 salaries". A cursor clicks "Ask AI". A "RAG pipeline trace" then types out "Vector DB scan complete → q4-salaries; Authz: Skipped (authorization disabled); 1 document passed to LLM; No permission checks. All retrieved docs sent to LLM." The AI answers with salary bands, and a red banner reads "No authorization check performed." Step 2, "Why RAG Leaks Data", shows four boxes in a row: User Query → Vector DB ("no authz check") → LLM ("full context, includes restricted docs") → Data Leak ("confidential exposed", red glow). — [AuthZed post](https://x.com/authzed/status/2072679204831768894)
- The demo page continues. Step 3, "RAG with Authorization Infrastructure", has SpiceDB doing "CheckPermission per doc ID… post-filter on metadata" under the heading "Retrieve first, check permissions second". Step 4 shows an access matrix with ✓/✗ per document per user (Q4 Salary Forecast: Alice ✓, Bob ✗). Step 5, "The Problem Compounds With Agents", shows two rows: "Acting as Bob → ✗ DENIED · Bob can't view salary data, so his AI assistant can't either" and "Acting as Alice → ✓ ALLOWED". — [AuthZed RAG demo page](https://authzed.com/ai-authorization/rag-demo)
- Metaphors and beats: no physical metaphor. The story is "same question, wrong user", then the leak as a red end-box, then a per-document ✓/✗ matrix, then the agent inherits the user's rights.
- Pacing: interactive, so the GIF is a 6 s loop of the leak only. On-screen text is dense, at UI-caption size.
- Layout, type and colour: dark UI, red/maroon for "authorization off" and the leak, monospace trace text, and ✓/✗ glyphs in the access matrix.
- **What to borrow:** (a) the "same question, two users, two outcomes" demonstration; (b) the 4-box pipeline that ends in a red "Data Leak" box as the "bad" path; (c) Step 5's two-row agent comparison ("the AI assistant can only see what the person it acts for can see"). **Do not copy** Step 3's "retrieve first, check second" fix: it is post-filtering, the opposite of this project's message.
